# แผนที่สต๊อกบ้าน Startup Up (stock-map)

เว็บแยกสำหรับ **ดูสต๊อกและแก้ไขจุดเด่น** — แสดงว่าแต่ละโครงการอยู่ตรงไหนบนแผนที่ บ้านแต่ละหลังอยู่ตรงไหน
แต่ละทำเลมีกี่โครงการ แต่ละโครงการมีกี่หลัง และ **บ้านที่ยังไม่เสร็จมีกี่หลัง อยู่ตรงไหน**

ทุกคนดูสต๊อกได้ ผู้ดูแลเว็บหลัก (Admin/Host) เข้าสู่ระบบ Google เพื่อแก้ไขจุดเด่นรายหลังได้ โดยไม่แก้ไขข้อมูลบ้านในเว็บหลัก

## ข้อมูลมาจากไหน

| ข้อมูล | ต้นทาง |
| --- | --- |
| รายการบ้าน + สถานะ + ทำเล + โครงการ | Google Sheet [`Stockบ้าน`](https://docs.google.com/spreadsheets/d/1fdVOGbCgUCRVI_uYDBDZK7Mz0sajTxu4z6e3xS2JDQ4/edit#gid=0) (แท็บแรก, gid=0) |
| พิกัดบ้านแต่ละหลัง | ลิงก์ Google Maps ในคอลัมน์ `Location` ของชีต |
| พิกัดสำรอง | คอลเลกชัน `properties` ของเว็บหลัก (Firestore, อ่านผ่าน REST แบบ public) |

### เกณฑ์การคัดบ้าน

- **เอาเฉพาะบ้านของ Startup Up** — ตัดรายการฝากขายออก (คอลัมน์ `หุ้นส่วน` = `3%`
  หรือคอลัมน์ `Website`/`หมดสัญญา` เขียนว่า `ฝากขาย`)
- **ตัดบ้านที่ขายแล้วออก** — คอลัมน์ `สถานะ` = `ขายแล้ว`
- แถวที่ `หุ้นส่วน` ว่าง ถือว่าเป็นบ้านบริษัท (ไม่ใช่ฝากขาย)

### การจัดกลุ่มสถานะ

| กลุ่มที่แสดง | สถานะในชีต | สี |
| --- | --- | --- |
| ยังไม่เสร็จ | `ยังไม่เสร็จ` | ส้ม |
| พร้อมขาย | `ว่าง` | เขียว |
| ติดลูกค้า | `ประเมิน`, `ยื่นกู้`, `ยื่นซ้อนได้`, `รอโอน` | น้ำเงิน |

## การหาพิกัด

เรียงตามความแม่นยำ — หมุดที่ได้จากสองข้อล่างจะเป็น **เส้นประ** และมีป้ายกำกับว่า "ตำแหน่งโดยประมาณ"

1. ลิงก์ Google Maps ในคอลัมน์ `Location` (แม่นยำระดับหลัง)
2. บ้านเลขที่เดียวกันในเว็บหลัก
3. ค่าเฉลี่ยพิกัดบ้านหลังอื่นในโครงการเดียวกัน
4. จุดกึ่งกลางของทำเล
5. ถ้าไม่มีเลย → ขึ้นในกล่อง "บ้านที่ยังไม่มีพิกัด" ท้ายหน้า (ยังนับรวมในสถิติ)

**อยากให้บ้านขึ้นแผนที่แม่นๆ**: ใส่ลิงก์ Google Maps ในคอลัมน์ `Location` ของชีต แล้วกดปุ่ม "ดึงข้อมูลใหม่"

### `data/geocache.json`

ลิงก์ Google Maps แบบย่อ (`maps.app.goo.gl`) ต้องยิง request ตามไปดูพิกัดปลายทาง ซึ่งช้าถ้าทำทุกครั้ง
ไฟล์นี้จึงเก็บพิกัดที่แปลงไว้แล้ว 428 ลิงก์ ลิงก์ใหม่ที่ยังไม่มีในไฟล์จะถูกแปลงสดตอนเรียก API
และแคชไว้ในหน่วยความจำของ server

อัปเดตไฟล์แคช (ทำเมื่อมีลิงก์ใหม่เยอะๆ เพื่อให้โหลดเร็วขึ้น):

```bash
node scripts/build-geocache.mjs
```

## รันในเครื่อง

```bash
cd stock-map
npm install
npm run dev     # http://localhost:3100
```

## Deploy

เว็บนี้อยู่ในโฟลเดอร์ย่อยของ repo หลัก ต้องสร้างเป็น **Vercel project แยกอีกอัน** โดยตั้ง Root Directory = `stock-map`

1. Vercel → Add New Project → เลือก repo `startupuprealestate/Web-startupup-v2`
2. **Root Directory**: กด Edit แล้วเลือก `stock-map`
3. Framework: Next.js (ตรวจอัตโนมัติ) — ไม่ต้องตั้ง env var อะไรเพิ่ม
4. Deploy

หรือผ่าน CLI:

```bash
cd stock-map
npx vercel --prod
```

> เว็บหลักยังคง deploy จาก root ของ repo เหมือนเดิม ไม่ได้รับผลกระทบ

## API

`GET /api/stock` — คืน JSON ที่จัดกลุ่ม ทำเล → โครงการ → บ้าน พร้อมยอดสรุป
แคชฝั่ง server 5 นาที, ใส่ `?refresh=1` เพื่อดึงใหม่ทันที


## จุดเด่นรายหลัง

- กดหมุดบ้านเพื่อดูจุดเด่น 3 ข้อแรก และกดดูเพิ่มเติมได้ จับคู่เว็บหลักด้วยชื่อโครงการและบ้านเลขที่ตรงกันเท่านั้น หากซ้ำหลายรายการจะไม่เดาเลือก
- Admin/Host ที่ยืนยันอีเมลแล้วใช้ปุ่มแก้ไขจุดเด่น ข้อมูลเก็บแยกใน `stock_map_highlights/{sha256(normalized project + house number)}` และอัปเดตทุกเครื่องที่กำลังดูหลังนั้น
- ข้อความที่บันทึกเอง รวมถึงข้อความว่าง มีลำดับก่อนเว็บหลัก ปุ่มกลับไปใช้ข้อมูลจากเว็บหลักบันทึกโหมด `website` โดยไม่ลบเอกสาร
- บันทึกแบบ transaction พร้อม revision ป้องกันการเขียนทับงานจากอีกเครื่อง จำกัด 4,000 ตัวอักษร เก็บเฉพาะข้อความสาธารณะ ไม่เก็บอีเมลผู้แก้ไขในเอกสารสาธารณะ
- `/api/website-highlights?project=...&number=...` อ่านข้อความล่าสุดเฉพาะหลังที่จับคู่ได้ บ้านใหม่ค้นหาด้วยบ้านเลขที่และตรวจชื่อโครงการซ้ำโดยไม่สแกนบ้านทั้งเว็บ แคชตอบกลับ 5 นาที ใช้ snapshot เมื่อเว็บหลักไม่พร้อม
- สิทธิ์ใช้ฐานข้อมูลเดิม `startup-up-realestate/(default)` โดยเพิ่มกฎเฉพาะ collection ใหม่ ไม่เปลี่ยนสิทธิ์ collection เก่า สำเนากฎก่อนแก้อยู่ใน `security/firestore.baseline.rules`
- Firebase Auth ต้องอนุญาตโดเมน `stock-map-startupuprealestate.vercel.app`

### ตรวจสอบก่อนปล่อย

`node --test tests/highlights.test.mjs`

ใช้ Java 21+ และ `firebase emulators:start --only firestore,auth --project demo-stock-highlights --config firebase.highlights.json` จากนั้น `node --test tests/highlights-rules.mjs`
